# تقرير V33 — تنظيف شامل محافظ على سلوك اللعبة

**المصدر:** V32 SOURCE (لم يتم تعديل أرشيف V32 الأصلي).
**الهدف:** تنضيف الكود وملفات المشروع بشكل مدروس وقابل للتحقق، من غير خسارة تعديلات الجيم بلاي السابقة أو حذف Assets ديناميكية عن طريق التخمين.

## 1. تنظيف الكود والأخطاء الحقيقية

1. **فصل بنك أسئلة True/Fake عن الكود:** نقل محتوى **500 سؤال** من ملف TypeScript ضخم (~7,507 سطر) إلى `true-fake-questions.json`، مع إبقاء `true-fake-content.ts` واجهة صغيرة تقرأ المحتوى وتتحقق من النوع والـ ID والتكرار واللغتين والتصنيفات والصعوبة. لم يتغير أي Question ID أو Answer أو Difficulty أو Tags أو ترتيب الأسئلة.
2. **إصلاح 34 سؤالاً في الإنجليزية:** بعض جمل `statement.en` كانت مكتوبة بالعربية أو معكوسة مع `statement.ar`، وهو خطأ واضح داخل بنك الأسئلة. تم تصحيح المحتوى اللغوي فقط. **لم يُغيَّر الحكم صح/غلط لأي سؤال.** الفحص الآلي يرفض بعد ذلك الإنجليزية المكتوبة بالعربية أو سؤالاً بلا ترجمة عربية.
3. **إصلاح خطأ Event typing محتمل:** في `MainScreenPlayFlow.tsx` كان `KeyboardEvent` مستورداً من React ويُستخدم في `window.addEventListener`. الآن الـDOM keyboard listener يأخذ نوع DOM الفعلي، واحتفظنا بـ`ReactKeyboardEvent<HTMLButtonElement>` داخل كروت الألعاب.
4. **توحيد مصدر الحقيقة لإظهار الترتيب والإضاءة:** كانت `VisualWorldLayer` تحتوي `setTimeout(4800)` يبدّل إضاءة كشف الإجابة قبل ضغط الهوست (رغم أن V32 أوقفت التقدم التلقائي). أصبح `GameplayOverlay` و`VisualWorldLayer` يستخدمان حالة UI مشتركة واحدة `RoundRevealCompletionContext` ومفتاح سؤال واحد `getScoringRevealKey`. لا يوجد تغير تلقائي بعد وقت معين، ولا تغيير في GameStore أو نقاط اللاعبين.
5. **إزالة كود UI ميت فقط:** إلغاء `ActionWarmupScreen`, `PrepareCountdown`, `AnswersLockedScreen` (تعريفات غير مستعملة) وإلغاء `StreamerControls.tsx`، وهي مجرد Wrapper غير مستدعى لـ`HostProductionPanel`. الإبقاء على `GameCanvas` كطبقة مسرح محفوظة للمؤثرات.
6. **إصلاح البنية الخاصة بالاختبارات والـScripts:** كانت 3 أوامر `package.json` تحاول تشغيل ملفات غير موجودة (`check:localization`, `audit:release`, `smoke:v2`). أصبحت لها Scripts تعمل بالفعل. أضفنا `eslint.config.js` لخيار lint بجانب TypeScript typecheck، مع أدوات سلامة جديدة.
7. **تحديث Assertion قديم بدل إضعاف الاختبارات:** اثنان من اختبارات V19 وV21 كانا يفحصان أسماء عناصر قديمة تغيرت أصلًا في V32؛ صار الفحص مرتبطًا بالعناصر الفعلية مع الحفاظ على هدف كل اختبار (الـreveal والأنوار).

## 2. تنظيف الملفات وتنظيمها

- أرشفة **36 مستند إصدار/Manifest قديمًا** في `docs/history/releases/`، مع فهرس يوضح أنها تاريخ وليست تعليمات النسخة الحالية. حذف ملف `PATCH_README_AR.md` المكرر حرفيًا من `PATCH_README_V19_AR.md` فقط.
- حذف **8 ملفات PNG غير مستعملة** حجمها معًا **6,508,258 بايت (~6.51 MB)**، بعد التحقق من عدم ورود أسمائها في `src/` أو إعدادات التشغيل:
  - أربع صور `choice_spotlight_1..4.png` القديمة.
  - `tour_mode_trophy.png` و`mini_game_mode_controller.png` (تم الإبقاء على الصور البديلة المؤطرة و SVG المستخدمة).
  - `shape_count_card_background.png` و`food_origin_card_background.png` (البطاقات الحالية تعتمد على الـSVG/الواجهة الجديدة).
- لا حذف لمسارات `stage-ready` أو تفاصيل sprites: ما زال يوجد **660 إطارًا منطقيًا** مع خريطة **278 Alias**. ولم يتم حذف صوت أو خلفية أو كرة/كوباية Lucky Cup أو ملفات QA-only games.
- الملفات في جذر المشروع كانت **46**، وأصبحت **10 قبل إضافة هذا التقرير وأدوات التوزيع**؛ الوثائق التاريخية لا تختلط بالتشغيل.
- **الحجم الخام قبل/بعد قبل تقرير الإصدار النهائي:** V32 نحو **72.10 MB**، V33 نحو **65.62 MB** (توفير حوالي **6.48 MB**). الأرقام تستثني `node_modules`، وملفات Build المحلية ونتائج الفحص المولدة.

## 3. أدوات تحقّق جديدة تمنع تكرار المشاكل

| الأمر | الغرض |
| --- | --- |
| `npm run verify:integrity` | فحص استيرادات TS/TSX/CSS والـJSON والأصول الثابتة وروابط scripts وحروف المسارات على Windows وتوقيعات الصور والتكرارات والـTrueFake والـReveal |
| `npm run smoke:v2` | اختبارات مصدر سريعة بدون Electron أو تنزيل حزم |
| `npm run verify:all` | تشغيل كل اختبارات Regression القديمة والجديدة الموجودة في scripts |
| `npm run check:localization` | فحص توافق ترجمة التطبيق + قائمة مراجعة Advisory للنصوص المضمنة في JSX |
| `npm run audit:release` | فحص الناتج الحقيقي بعد `npm run build` (Vite/Electron/preload/assets) |
| `npm run cleanup:v33` | عرض الملفات القديمة الممكن حذفها من V32 بدون حذف افتراضي |
| `npm run cleanup:v33 -- --apply` | حذف SHA-256-match فقط؛ يترك أي ملف معدّل أو غير متوقع سليمًا |

## 4. اختبارات نُفّذت بالفعل

- **41/41 Scripts تحقق إصدار موجودة نجحت** بعد تحديث اختباري V19/V21 القديمين (يتضمن شكل الأسئلة، مكان إجابة الهوست، Lucky Cup V27–V30، وحدات CSS، النقاط، Registry الألعاب والمراحل).
- **فحص أمان Electron: 24 نجاح / صفر إخفاق**.
- **تحليل صياغة TypeScript/TSX: 137 ملفًا بدون Parse Errors** باستخدام TypeScript Compiler API متوفر في بيئة الفحص.
- **فحص TypeScript للـTrueFake content + QuestionBank graph: صفر Diagnostics** (فحص مستقل لمكوّن Game Core).
- **فحص المصدر:** 521 استيرادًا نسبيًا + 17 استيراد CSS + 91 رابط Asset ثابت + 506 أصلًا عامًا تم التحقق منها؛ لا تكرار متطابق للـAssets المنشورة.
- **بنك True/Fake:** 500 سؤال فريد مع ترجمتين؛ جميع IDs والإجابات والصعوبة والتصنيف ثابتة.

### حدود الإثبات — مهمة

- لم يكن بالإمكان تثبيت كل Dependencies من Registry في بيئة التنفيذ، لذلك **لم يُجرَ `npm ci` ناجح ولا `npm test` (Vitest) ولا `npm run build` مكتمل ولا تشغيل Electron على Windows**. الفحص النحوي للـTS ليس بديلًا عن الـTypecheck الكامل.
- CSS لا يزال يحتوي **42 ملفًا وحوالي 10,891 `!important`**؛ هناك نحو 31.5 ألف سطر من CSS القديم. أي حذف آلي واسع أو تغيير ترتيب Cascade ممكن يفسد الواجهة، لذلك **لم يتم** باعتباره تنظيفًا عالي المخاطرة بدون QA بصري.
- `game-store.ts` لا يزال ملفًا كبيرًا يحتاج تقسيمًا تدريجيًا باختبارات تدفق Tour وحالات المزامنة، وليس تغييرًا شاملًا عشوائيًا في نسخة تثبيت UX الحالية.
- التحقق من حركة الستارة والهوست والـFull Tour بصريًا وبـTwitch الحقيقي يحتاج تشغيل التطبيق على Windows. لا يوجد ادعاء أن النسخة خالية من كل عيب Runtime.

## 5. طريقة الاستخدام

**أنصح بالنسخة الكاملة (SOURCE)**: فكّيها في فولدر جديد وفاضي، ولا تدمجيها مع النسخة القديمة. ده السبيل الأضمن فعليًا للتخلص من الملفات القديمة.

```powershell
npm ci
npm run verify:integrity
npm run smoke:v2
npm run verify:cleanup
npm run verify:all
npm test
npm run build
npm run audit:release
npm run dev
```

**لو هتستخدمي PATCH فوق V32**: خدي نسخة احتياطية من المشروع الأول، انسخي الملفات فوق المشروع، وبعدين اعملي Dry-run وتنضيف آمن للملفات القديمة:

```powershell
npm run cleanup:v33
npm run cleanup:v33 -- --apply
```

الـScript يستخدم Hashات الملفات القديمة ولا يلمس أي ملف اتغير من جانبك.
