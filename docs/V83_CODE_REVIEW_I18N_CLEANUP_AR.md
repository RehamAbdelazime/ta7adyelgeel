## 4. نقاط Code Review المتبقية (غير مغطاة، بدون إخفاء)

1. **رسائل نظام Twitch/Electron:** الخدمات المكتبية مثل `TwitchAuthService` و`TwitchIrcClient` فيها حالات وأخطاء تقنية بالإنجليزية، وبعضها قد يظهر للمستخدم بعد مروره عبر IPC. الأفضل في خطوة مستقلة تعريف Error/Status codes ثابتة من الخلفية وترجمتها في واجهة العرض حسب اللغة، بدل تغيير رسائل أخطاء الـOAuth الخام قد يعرقل التشخيص.
2. **`GameStore` كبير ومتعدد المسؤوليات:** يستحق فصل توليد Awards والـScoring/Tour snapshots لخدمات متخصصة، لكن إعادة هيكلته دفعة واحدة مع الـi18n مخاطرة غير لازمة، فتركنا منطق V82 مُختبرًا.
3. **`MiniGameIntroIllustration` ديكور قديم غير مركّب في الواجهة النشطة:** وجوده مع أنماط CSS قديمة ممكن يتشال في Cleanup CSS مخصص بعد التأكد من عدم الاعتماد عليه في اختبارات تاريخية. الشروحات المستخدمة فعليًا هي مكونات صفحتين.
4. **محتوى أسئلة الصور والأفلام والأكلات:** ده محتوى تحريري وبنوك بيانات، وليس Hardcoded UI ثابتًا. يفضل يبقى منفصلًا عن `TranslationKey` إلا في حالة إنشاء Content Localization Pipeline.
5. **فحص أداء وVisual QA:** تشغيل Electron على Windows بمقاسات 720p/1080p، والتأكد من محاذاة RTL وقراءة النصوص الطويلة، شرط قبل تسميته Release-ready.
