# تحدي الجيل — مراجعة Senior React + UI/UX لنسخة الكمبيوتر

**التاريخ:** 2 نوفمبر 2026  
**النطاق:** Electron / React 19 / TypeScript / شاشة PC ثابتة بنسبة 16:9 / بث Twitch / العربية والإنجليزية.  
**المرجع:** الملفات المصدرية التي رُفعت باسم `ta7adyelgeel_source.rar`، وليس نسخة أخرى من المشروع.

> **الحالة:** تم تنفيذ دفعة إصلاحات عملية داخل الملفات المرفقة، مع تدقيق برمجي وتحليل CSS والتحقق من اختبارات التكوين. **هذا لا يمثل شهادة أن واجهة اللعبة خالية من كل العيوب بصريًا**؛ لم يتوفر تشغيل Electron مع حساب Twitch حي، ولم تنجح تجربة التقاط لقطات Chromium في بيئة المراجعة. يجب اجتياز بوابة جودة مرئية على Windows قبل عرضها رسميًا.

## ملخص تنفيذي

الهوية الفنية (مسرح، شخصيات، أزرق سماوي/بينك، وتكوين 16:9) تصلح كأساس لواجهة جذابة. المشكلة الأساسية ليست قلة المؤثرات، بل **غياب الانضباط البصري والتفاعل الموحد**: CSS متراكم من تعديلات متتابعة، عدة مسارات فيها سلوك مربك للمستخدم، وحالات ناقصة في الترجمة وإمكانية التحكم بالكيبورد. اللعبة تستهدف الكمبيوتر فقط؛ لذلك الأولوية لشاشة stage ثابتة، Mouse + Keyboard، دقة العرض المختلفة، عدم حجب المحتوى، وإدارة العرض أمام الجمهور.

- **11** ميني جيم مسجلة، منها **8** متاحة للعامة و**3** للاختبار فقط (وفق Registry).
- ملف `src/ui-react/styles.css` يتجاوز **31 ألف سطر** ويحتوي على نحو **7,800 استعمال `!important`**. هذا مؤشر صيانة عالي الخطورة، وليس خللًا مرئيًا مثبتًا بمفرده.
- حجم `public/` نحو **105MB** من الأصول، وبعض الصور عدة ميجابايت. يلزم تدقيق استهلاك الذاكرة وسرعة التنقل لا الاكتفاء بحجم الملف.
- شاشة الإعدادات والقوائم كانت تحتوي على أعطال تفاعل محددة قابلة للإصلاح (موثقة أدناه).

## 3. مواصفات UI/UX للنسخة Premium (Desktop only)

**Design system:** تثبيت الخلفية بدرجة لونية عميقة؛ السماوي لمعلومات اللعبة والتفاعل الأساسي، والبينك للتحديد/الإبراز فقط، والذهبي للتنبيه. تقليل الظلال المتراكبة والحدود النيون في العناصر الثانوية. تعريف حالات واحدة للأزرار: Default / Hover / Focus / Pressed / Disabled / Loading. استخدام 4–6 مستويات خط واضحة بدل تصغير الكلمات لتلائم المكان.

**Stage layout:** المسرح 1920×1080 بتصغير موحد داخل نافذة Electron؛ ممنوع تمديد الخلفية على 21:9. تُحدد منطقة آمنة للمحتوى لا تتداخل مع الـ Host والشخصيات. استخدام قياسات مرتبطة بحاوية المسرح `cqw/cqh` وعناصر بنسب قياسية، لا خلط عشوائي بين `vh`, `vw`, `px`.

**رحلة المستخدم:** شاشة دخول مفهومة مع معالجة انتظار وربط Twitch؛ Lobby تُظهر اللاعبين المشاركين وتعليمات `!join` بوضوح؛ Play → اختيار الوضع → اختيار الألعاب → Confirmation عند الحاجة → مقدمة قصيرة → سؤال → كشف إجابة → لوحة نتائج → جولة تالية. في كل شاشة زر رجوع/استمرار واضح وحالة انتظار لا تختفي دون تفسير.

**الميني جيمز:** قالب موحد لعنوان السؤال، المؤقت، مساحة الصورة/الحركة، الإجابات، وإرشادات Twitch. ينطبق على **Food Origin، Shape Count، Maze Gates، Before or After، Guess the Logo، Count the Beat، Lucky Cup، True or Fake**؛ الألعاب الأخرى QA-only لا تُعرض للمستخدم النهائي قبل اختبارها.

**Motion:** حركات انتقال ذات معنى وزمن مناسب، لا حركة مستمرة على كل عنصر. الاحتفاظ بحركات لازمة لقواعد اللعب، وتخفيف الزخارف عند `prefers-reduced-motion`. قياس Frame time عند تشغيل Twitch ووصول رسائل كثيرة.

**Accessibility:** التباين المناسب للنص الصغير، تركيز مرئي بالكيبورد، أسماء صحيحة للأزرار، Tab order منطقي، Escape للإغلاق/الرجوع دون تخطي سؤال بالخطأ، والتأكد أن نافذة الإعدادات لا تسمح بالضغط على الخلفية.

## 4. خطة تنفيذ آمنة لا تكسر اللعبة

**المرحلة A — استقرار وعرض:** إغلاق P0/P1 المتبقية، وتوحيد قالب السؤال والمقاسات وتدفق الدور. إعداد بيانات QA وهمية محلية للعرض مع فصلها عن نظام Twitch الحقيقي؛ تسجيل لقطات مع وبدون مشاركين؛ إعداد لقطة لكل حالة.

**المرحلة B — Design system:** عمل مكتبة React components بسيطة (`GameButton`, `Panel`, `StatusBadge`, `QuestionShell`, `Modal`, `ScoreCard`)؛ تفكيك CSS إلى وحدات؛ تقليل `!important` تدريجيًا مع مقارنة صور مرجعية. لا تبدأ تحسينات VFX قبل تثبيت التخطيط.

**المرحلة C — Visual polish:** توحيد المسافات، قواعد الخطين العربي والإنجليزي، توازن المسرح والشخصيات وChat UI، مؤثرات hover/transition واهتزازات المؤقت، وتخفيف الأصول.

**المرحلة D — Release gate:** اختبارات آلية + مراجعة على جهاز Windows + اختبار تفاعل حقيقي أو Mock مطابق لتويتش؛ إصلاح أي عيب P0/P1 قبل تقديم اللعبة للمحترفين.

## 6. نتائج التحقق الفعلية في هذه الجلسة

**نجحت:**
- سكربت التحقق من 11 لعبة مسجلة / 8 عامة / 8 مفعلة.
- التحقق من تنسيق صفوف اختيار الألعاب وعددها.
- التحقق من Scoring Policy دون تغييرها.
- فحوص Landing الأساسية وLanding Identity بعد إعادة الاسم والسطر التعريفي.
- فحص Visual Refresh ومراجعته البنيوية.
- فحص `verify-desktop-ux-hardening.mjs` المضاف، وفحص Final Flow Lock.
- فحص Security Audit الخاص بالمشروع بعد تفعيل Renderer sandbox (مع احتياج تجربة فعلية لـ preload في Electron).
- تحليل صياغة **120** ملف TS/TSX بدون Parse Errors (باستخدام TypeScript parser).
- تحليل `styles.css` باستخدام CSS parser بدون أخطاء parse.

**حدود المراجعة:** `npm ci` لم يكتمل في بيئة التنفيذ بسبب عدم توافر اتصال npm registry، ولذلك لم أتمكن من تشغيل `npm run typecheck`/`npm test`/`npm run build` كاملًا، ولم أضع علامة نجاح وهمية. كما لم يتوفر Visual QA موثق بقطات من Electron على Windows؛ محاولة Chromium headless لم تُنتج Screenshot. يوجد **سكريبت تحقق قديم منفصل لنسخة Mode Picker** (`verify-v2-mode-picker-target-layout.mjs`) يبحث عن علامة CSS قديمة غير موجودة في هذه النسخة؛ فشله لا يُفسَّر تلقائيًا على أنه عيب مرئي، لكنه يدل على أن سكربتات التحقق القديمة تحتاج تنقية.
