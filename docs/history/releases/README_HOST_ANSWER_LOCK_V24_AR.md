# v24 — قفل إجابة الهوست بعد أول إرسال ناجح

**الوضع المطلوب:** كل سؤال يقبل إجابة واحدة من الهوست، وتختفي فقاعة الإدخال بمجرد قبولها، دون السماح بتغيير الإجابة من الـUI أو الشات. تبدأ فقاعة جديدة مع السؤال التالي.

## التنفيذ

- `GameStore` يحتفظ بحالة `privateStreamerAnswerSubmitted` لكل سؤال، وليس داخل React component فقط.
- بعد أول إجابة ناجحة من الهوست، يرفض Store أي إرسال جديد إلى نهاية السؤال، حتى بعد إعادة ربط حساب Twitch أو تغير ID المستخدم، ويمنع تعديل الإجابة من شات البث بواسطة صاحب القناة.
- إذا أجاب الـBroadcaster من Twitch أولًا، تقفل فقاعة الهوست أيضًا.
- الحالة تُصفَّر مع فتح نافذة إجابات السؤال التالي فقط؛ لذلك لا يفك القفل بسبب تغيير اللغة أو إعادة Render أو إيقاف المؤقت مؤقتًا.
- `PrivateStreamerAnswerDock` لا يُعرض عند تفعيل القفل. لم يُعَد تصميم الفقاعة ولم تتغير قواعد CSS أو الألوان أو النقاط.
- ألعاب الأسئلة ذات الاختيارات أصلًا تحتفظ بأول إجابة مقبولة لكل مشاهد، ولا تسمح بتعديلها. Hangman لعبة تخمين حروف متتابع، وليست نظام إجابة واحدة قابلة للتغيير؛ لم نغيّر قواعد تخمين المشاهدين فيها من خلال هذا التحديث.

## الاختبارات

تم تشغيل اختبار تكاملي فعلي على كود `GameStore` بعد تحويل TypeScript إلى CommonJS لأغراض الاختبار (بدون Electron)، وكانت النتائج:

1. أول إجابة هوست تُقبل، تليها إجابات ثانية مرفوضة (حتى بعد تغيير Twitch ID)، وإجابة الشات لا تستبدل الأولى.
2. إذا أجاب الـBroadcaster من الشات أولًا، لا يمكنه الإجابة ثانية من فقاعة الهوست.
3. أول إجابة للمشاهد في Food Origin تبقى محفوظة ولا يستبدلها أمر آخر.
4. الانتقال للسؤال الثاني يفتح القفل مجددًا.
5. فحص صياغة TypeScript/TSX للملفات المعدلة والإضافية نجح.

تمت إضافة اختبارات Vitest داخل `src/game-core/app/host-answer-lock.test.ts` لتشغيلها مع `npm test` على جهازك. **لم يكتمل هنا Build كامل ولا اختبار Electron على Windows**.
